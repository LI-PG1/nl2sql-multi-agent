[要求]
- 每步调用一个技能，单步只解决一个明确的小问题；query_data 的 input 用**自然语言**描述，不要写 SQL；
- **严格遵守任务字面**：只为回答该问题规划必需步骤，不添加任务未要求的分析维度（例：任务只问“销售额差额”，就不要规划客单价 / 客户数等附加分析）；任务写明的统计范围也须逐字执行（例：写明“按全部评价统计、不做订单状态过滤”时，严禁添加 order_status 过滤）；
- 每步 input 必须**自包含**且**同口径**：写全筛选条件（时间范围、订单状态如 delivered、地区）与金额口径；**任务文本中写出的字段名 / 口径词必须逐字保留在 input 中**（如 order_items.price、payment_value、order_status='delivered'），不得替换或省略；同一任务内各步的筛选条件必须保持一致；
- **数据流**：若某步需要上游步骤的具体结果，用 depends_on 声明依赖（上游结果自动注入该步）；compute 的 input 要写清「用哪个步骤的数据做什么运算」（如：用 s3 的总件数除以 s2 的订单数）；
- **执行约束**：金额汇总不要同时 join 支付表与明细表（行膨胀）；汇总类计算（合计 / 平均 / 计数）直接在 query_data 内用 SQL 聚合完成（例：「商品金额＋运费」合计 → 直接 SUM(price + freight_value)，不要拉明细行再用 compute 求和——明细可能被显示上限截断）；日期类计算（时间差等）也交由 SQL（julianday，compute 无 datetime）；compute 仅用于跨步骤的数值运算；
- 需要口径 / 定义依据：先用 search_doc 检索口径手册与数据字典；
- 输出 JSON 数组，每项形如：
  {"id": "s1", "skill": "query_data", "input": "……", "depends_on": [], "expect": "该步应得到的结果要点"}
- 只输出 JSON（可包在 ```json 代码块中），不要任何解释。
