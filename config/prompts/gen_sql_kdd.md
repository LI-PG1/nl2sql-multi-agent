[解题纪律（逐条遵守）]

一、先定题型，再写 SQL。三类题型对"去重 / NULL / 行集"的处理完全不同：
  1. **列出原始记录**（题面为 show / list / 列出 / 展示 / 有哪些记录 / retrieve 某指标的全部数据）：
     输出题面要求的目标列，**保留原始行集**——不去重、不排序（题面未要求时）、不过滤 NULL、不加 LIMIT；
     重复值与空行都是有效数据（评分为取值多重集匹配，**空行也是签名的一部分**）。
  2. **实体名单判定**（题面为 哪些 X / which X qualify / 满足条件的实体）：
     目标列是实体标识（名称 / ID / 代码）时，同一实体在多行重复出现 → 必须按实体 **DISTINCT** 去重。
  3. **聚合 / 排名 / 计数 / 数值比较**：
     按题面要求的粒度聚合（GROUP BY 分组维度完整）；涉及数值比较、均值、排名时，
     显式排除 NULL（WHERE col IS NOT NULL），避免 NULL 混入结果。

二、列选择：只输出题面**明确要求**的字段。
   - 仅当题面要求定位实体、分组、排名、TopN、时间序列标签，或结果必须依赖辅助字段解释时，才输出辅助列；
   - 题面未要求的列一律不输出（多余列会导致判分失败）。

三、字段语义映射：字段名相近 ≠ 同一指标。
   - 单位、口径、周期、维度不同的同名字段不是同一指标（如"含税/不含税""年度/季度""累计/当期"）；
   - 以 [背景提示] 与表结构中的定义为准，找不到语义对应的字段时不要用相近字段硬凑——优先按下方"文档检索"取值。

四、SQL 陷阱（逐条核对）：
   - 极值题（最低 / 最高 / 最大 / 最早的并列）：用 `WHERE col = (SELECT MIN(col) FROM ...)` 而非 `ORDER BY col LIMIT 1`，除非题面明确"only one / 第一"；
   - 对列排序时排除 NULL（否则 NULL 可能排在最前/最后污染结果）；
   - 时间字符串（如 "1:32.456" 或中文日期）排序前先转数值/标准格式，不能按字典序；
   - 表名 / 列名含中文或特殊字符（括号、百分号、空格）时，必须用双引号包裹标识符；
   - 涉及分类判断（normal / abnormal 等）时显式处理 NULL，不让 NULL 隐式归入某一类。

五、行数自检：写出 SQL 前先估算结果行数是否符合题面粒度（"每地区一行"→ GROUP BY 地区；
   "全部明细"→ 不加聚合）。行数明显不符（如明细题返回一行）时必须重写。

六、文档检索：题面指向"资料 / 报告 / 档案 / 简报"，或所述的表在数据库内不存在时，
   检索 doc_chunks 表（字段 file / seq / text）：`SELECT text FROM doc_chunks WHERE text LIKE '%关键词%'`，
   取原文后用解读阶段作答。
