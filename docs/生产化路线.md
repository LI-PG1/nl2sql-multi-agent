# 生产化路线（data-agent）

> 目的：把「研发验证工程」与「生产系统」之间的差距**显性化**——现状到生产，每一环差什么、怎么补、量级多大。
> 本文不是承诺清单，而是**迁移地图**；所列"现状"全部有仓库内证据（代码位置 / 报告 / 实测数字）。

## 一、已经是「生产模式」的部分（设计层，可直接迁移）

| 机制 | 实现位置 | 生产对应物 |
|---|---|---|
| 语义 / 口径层（指标定义、同义词、表说明、时间与金额口径） | `config/metrics.yaml` 等 4 表 + 注入链路 | 语义层（Semantic Layer） |
| 只读护栏（sqlglot 解析级 SELECT-only、单语句、禁 DDL/DML、自动 LIMIT） | `src/guard.py` | SQL 网关 / 权限前置 |
| 澄清与拒答（口径歧义主动澄清；变更类请求显式拒绝） | `src/graph.py` 澄清回路 | 对话式澄清策略 |
| 可靠性（环节级重试 ≤2、超时、并发闸、沙箱 10s 超时杀、max_iter 降级不中断） | `src/graph.py` / `src/sandbox.py` / `src/llm.py` | 生产可靠性工程 |

## 二、差距矩阵（现状 → 生产要求）

| 维度 | 现状 | 生产要求 | 迁移动作 | 量级 |
|---|---|---|---|---|
| 交付形态 | 单机 CLI ＋ 演示级 HTTP（单实例） | 多副本、灰度、回滚、SLA | 容器化 → K8s/网关（复用团队既有栈） | 天 |
| 数据平面 | 单机 SQLite（143 MB 演示库；放大压测 1,126 万行已做） | 数仓只读账号、执行下推、元数据同步 | 连接器（如 Trino/Hive/ClickHouse）+ 方言转译开关（sqlglot 已实证） | 周 |
| 权限 / 合规 | 语句级只读护栏 | 表 / 列白名单、行级权限、脱敏、审计留痕 | 网关侧策略 + 查询审计日志 | 周 |
| 并发与配额 | 进程内 Semaphore（4） | 队列、限流、多租户隔离 | 接队列（Redis/MQ）+ 用户配额 | 周 |
| 可观测 | 文件 trace | 指标（延迟 / 成功率 / token 成本）+ 告警 | 接 Prometheus / OTel；trace 上报 | 周 |
| 成本治理 | LLM 生成上限（粗粒度） | 预算 / 缓存 / 降级 | 语义缓存（问题→SQL）+ token 预算器 | 周 |
| 质量门禁 | 手动跑评测 | CI 门禁（回归不过不发布） | 评测脚本接入 CI（黄金集 + 外测抽样） | 天 |
| 人工兜底 | 无 | 高风险查询人工确认 | HITL 审批流（按表 / 金额阈值） | 周 |
| 需求侧 | 单轮问答 + 多步分析 | 与 BI / 报表体系集成、定时报告 | 报表任务化（把多步任务存为可调度作业） | 周 |

## 三、分阶段路径

- **P0（已完成）**：服务化外壳 + 引擎 / 方言解耦实证 + 规模压测（`service.py`、`eval/report_scale_lab.md`）。
- **P1 数据面对接**：数仓连接器（只读）→ 方言转译开关上线 → 口径层从 YAML 迁到语义层服务（带版本与审批）。
- **P2 服务治理**：队列 / 限流 / 多实例 → 指标与告警 → token 预算与语义缓存 → CI 评测门禁。
- **P3 组织级**：多租户、行级权限与脱敏、HITL、审计合规。

## 四、评审要点（一页答案）

- **"数据量小？"** —— NL2SQL 系统层不承载数据：生成的 SQL 在库上执行（下推），系统只碰 schema、口径与聚合结果。本项目持有真实数据 8 套 / 3.3 GB（主库 155 万行；外测 BIRD 11 库约 390 万行）；规模与引擎行为有实测：1,126 万行事实表压测 + 双引擎一致性（`eval/report_scale_lab.md`）。
- **"能上生产吗？"** —— 以"直接部署"为标准：不能，缺的是一层交付治理（见 §二、§三），且任何作品工程都如此；以"设计可迁移性"为标准：护栏、口径层、评测闭环、可靠性、trace、服务化均在，且关键环节（服务化 / 引擎 / 规模）已有可运行原型与实测数字。差距与路径即是本文。
